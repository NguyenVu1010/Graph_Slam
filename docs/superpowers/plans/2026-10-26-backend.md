# backend (GTSAM factor graph, iSAM2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill in `mss::backend::Graph`: a keyframe factor graph (pose, velocity, IMU bias per keyframe) optimised incrementally by iSAM2, with a custom 9x9 IMU preintegration factor, LiDAR / loop between factors, a GNSS position factor with lever arm, a wheel-odometry factor that handles a singular covariance, marginal covariances in mss order, and a no-GTSAM stub with the same API.

**Architecture:** `graph.hpp` stays GTSAM-free (pimpl). `core/backend/src/` holds the GTSAM side: `conversions` (Pose <-> Pose3, `[rho, phi]` <-> `[phi, rho]` permutation, keys), three custom `NoiseModelFactorN` factors (IMU, GNSS, odom) with analytic Jacobians, and `graph.cpp` (Impl: `unique_ptr<gtsam::ISAM2>`, pending/committed factor lists, per-keyframe initial guesses). LiDAR and loop use `gtsam::BetweenFactor<Pose3>` (loop wrapped in a Cauchy kernel). With `MSS_WITH_GTSAM=OFF`, `graph_stub.cpp` replaces `graph.cpp`; both share `validate.cpp`. The CMake target becomes `STATIC` with GTSAM linked `PRIVATE`.

**Tech Stack:** C++17, Eigen 3.4, GTSAM 4.2 (WSL `~/opt/gtsam` reports `4.2a9`, `GTSAM_POSE3_EXPMAP`, `GTSAM_ROT3_EXPMAP`, `GTSAM_TANGENT_PREINTEGRATION` defined; boost::optional Jacobian arguments), GoogleTest, CMake, WSL build via `tools/wsl/build.sh`.

## Contract issues

1. **No accessor for optimised keyframe states other than the latest.** `optimize()` returns only the latest keyframe; ADR-005 says the backend sends corrected keyframe poses to the front-end map, and B-02/B-03/B-04 must check every keyframe. Proposed (additive): `common::Result<common::NavState> keyframe_state(common::KeyId k) const;` (error for unknown / not-yet-optimised `k`). This plan does not add it: tests reach the state through `friend struct GraphTestAccess;`, an additive private declaration in `graph.hpp` (Task 2), defined in the internal `core/backend/src/graph_impl.hpp`.
2. **A zero random walk is legal by the header (throws only for `< 0`) but cannot be a sigma.** The bias `BetweenFactor` with sigma 0 is a hard constraint that iSAM2's Cholesky rejects. `pipeline/src/config.cpp` already requires `> 0` (`Range::kPositive`). Proposed: the constructor throws for `<= 0`. Planned behaviour without that change (Task 4): when either random walk is `0`, all keyframes share one bias variable `B(0)` (constant bias), no bias between factor is added, and the constructor logs one warning naming the ignored non-zero random walk (planner's call).
3. **ADR-004 says the IMU enters as `CombinedImuFactor`; `graph.hpp` (frozen, newer) says a custom 9x9 factor, NOT `CombinedImuFactor`.** CLAUDE.md requires an ADR before contradicting one. Task 1 writes `docs/adr/015-backend-custom-imu-factor-and-robust-loop.md` (number to be confirmed by the controller) and adds it to `docs/adr/README.md`.
4. **No config key for the loop robust kernel.** B-03 needs a kernel width; `BackendConfig` has none. Proposed: `backend.loop_cauchy_k` (dimensionless, Mahalanobis units, `> 0`, default `3.5485`) in `BackendConfig`, `config/default.yaml`, `pipeline/src/config.cpp`. Planned without it: named constant `kLoopCauchyK = 3.5485` in `graph.cpp`, `= sqrt(chi2_6(0.95)) = sqrt(12.5916)` (planner's call), cited in ADR-015.
5. **The non-holonomic factor has no entry point.** `add_odom_factor` says the O-02 constraint "is a separate factor designed by the odom/backend modules", but `Graph` has no `add_*` for it and no `T_b_o` / sigma (odom plan Contract issue 2). Out of scope here. Proposed: `void add_nonholonomic_factor(common::KeyId k, const common::Vec3& omega_b_radps);` plus `T_b_o` in the constructor and `wheel_odom.nonholonomic_sigma_mps`.
6. **Comment-only edit to `graph.hpp`:** "Contract only: graph.cpp is not written yet" becomes "stub: `src/graph_stub.cpp`" (Task 2). No signature changes. The PR notes items 1 and 6.

## Review Focus

1. **IMU factor rejected in the middle of the chain** (e.g. time check fails for 1->2, then 2->3 is accepted): `V(2)`, `B(2)` would enter the graph with no link to keyframe 0 and make the system indeterminant forever. Expected: the accepted factor re-anchors `V(i)`, `B(i)` with the first-keyframe prior sigmas centred on the guess, and `optimize()` succeeds. Test `BackendGraph.ImuGapReanchorsVelocityAndBias` (Task 4).
2. **Latest keyframe has no factor yet** (keyframe added, its LiDAR factor not yet produced): `optimize()` must not insert an unconstrained variable. Expected: ok, `state` = the keyframe's `x0`, `cov` all NaN, `keyframe_id` = latest; `marginal_cov(latest)` NaN. Test `BackendGraph.LatestKeyframeWithoutFactorsReturnsGuessAndNanCov` (Task 4).
3. **Non-finite or non-positive-definite covariance** in a LiDAR, loop, GNSS or IMU input (zero matrix, NaN entry, negative eigenvalue): rejected with one log line, never reaches GTSAM; the next `optimize()` succeeds. Test `BackendGraph.RejectsBadCovariances` (Task 4).
4. **Odom covariance rank 3, rotated by a non-trivial `T_b_o`** (zero directions not axis-aligned), and an all-zero covariance (`t0 == t1`): the factor has exactly 3 whitened rows and correct Jacobians; the all-zero delta is rejected. Tests `BackendFactors.B01_OdomFactorRotatedSingularCov`, `BackendGraph.RejectsBadCovariances` (Tasks 3, 4).
5. **Repeated `optimize()` with nothing pending, and two identical runs**: no crash, the estimate is unchanged to 1e-12 after convergence, and two `Graph`s fed the same calls give bit-identical `Estimate`s. Test `BackendGraph.RepeatedOptimizeIsStableAndDeterministic` (Task 5).

     Jacobians (GTSAM charts, so no permutation), `Jri = Jr^-1(r_phi)`:
     - `X_i`: `d r_phi = [-Jri R_j^T R_i, 0]`; `d r_p = [dR'^T skew(A), -dR'^T]`; `d r_v = [dR'^T skew(C), 0]` (columns `[dphi, drho]`).

     - `B_i` columns `[dba, dbg]`: `d r_phi = [0, -Jri Exp(r_phi)^T Jr(theta) J_dR_bg]`; `d r_p = [-dR'^T J_dp_ba, skew(r_p) Jr(theta) J_dR_bg - dR'^T J_dp_bg]`; `d r_v = [-dR'^T J_dv_ba, skew(r_v) Jr(theta) J_dR_bg - dR'^T J_dv_bg]`.
     Each line derived from `Exp(phi)^T u ~ u + skew(u) phi` and the lie_conventions Jr identities.

Loop: `Robust::Create(mEstimator::Cauchy::Create(kLoopCauchyK), Gaussian)`; GTSAM reweights on the whitened norm `|e|`, weight `1 / (1 + (|e|/k)^2)`; `k = sqrt(chi2_6(0.95)) = 3.5485`. Degeneracy report: diagnostics only (count of keyframes `j` with any flag).
  6. *GNSS.* Variable `X_k`; constants `T_e_w`, `p_b_g`. `r = R_e_w (R_w_b p_b_g + p_w_b) + p_e_w - p_e_g` (header sign; opposite of `gnss::detail::gnss_residual`). Jacobian `[-R_e_w R_w_b skew(p_b_g),  R_e_w R_w_b]` (columns `[dphi, drho]`). Noise `Gaussian::Covariance(m.cov)`.
  7. *Odom.* Variables `X_i, X_j`. `r_m, J_m_i, J_m_j` from `odom::relative_pose_residual(T_i, T_j, odom.T_b0_b1)` (mss order). `cov = U diag(lambda) U^T` (`SelfAdjointEigenSolver`, ascending); keep the `n` columns with `lambda > kOdomRankRelTol * lambda_max`, `kOdomRankRelTol = 1e-9` (planner's call, a numerical rank tolerance, not a tunable); `W = diag(lambda_kept)^-1/2 U_kept^T` (`n x 6`). Factor residual `W r_m`, Jacobians `W J_m P`, noise `Unit(n)`. `n = 0` or non-finite: rejected.
  8. *Marginals.* `ISAM2::marginalCovariance(X(k))` is `[phi, rho]` at the current estimate, right perturbation; returned as `P Sigma P^T`.
  9. *Failure handling and IMU-gap re-anchor* (one paragraph each, as Task 4 Step 3 states).
  10. *Checks* table: formula -> test name (filled as tasks land).
