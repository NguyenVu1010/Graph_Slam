# imu Module (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill in `mss::imu`: on-manifold IMU preintegration (mean, five bias Jacobians, 9x9 covariance, first-order bias-corrected prediction) and the static gravity/gyro-bias initialiser, with the tests I-01..I-05.

**Architecture:** `Preintegrator` integrates the scheme GTSAM `ManifoldPreintegration` uses (Euler, right perturbation, `dR <- dR * Exp(w dt)`, p/v with the old rotation). It propagates the covariance in GTSAM's NavState chart `[phi, p, v]`, so the backend uses it without permuting. All state is fixed-size members, and the hot path neither allocates nor throws. `ImuInitializer` is a stateless two-pass mean/std over a `Span`. The imu module never includes GTSAM. The GTSAM cross-check (I-03) is a test under `tests/unit/backend/`.

**Tech Stack:** C++17, Eigen 3.4 (fixed-size), `mss/common/lie.hpp` (Sophus wrapper), GoogleTest; GTSAM 4.2.0 in the I-03 test only.

**Spec:** `core/imu/include/mss/imu/{preintegrator,initializer,trajectory,config}.hpp` (frozen contract); `config/default.yaml` (`imu.*`); `docs/Test_CI_CD.md` `### imu — preintegration` (I-01..I-05); `docs/conventions.md`; `docs/derivations/lie_conventions.md`; ADR-003, 004, 005, 006, 008, 009, 011, 013; `CLAUDE.md`.

## Contract issues

1. **The pinned GTSAM build uses TangentPreintegration, not the Forster/manifold scheme the header assumes.**
   - *What:* GTSAM 4.2.0 built with default options (`docker/deps.Dockerfile`, `tools/wsl/setup.sh`) defines `GTSAM_TANGENT_PREINTEGRATION`. This was verified in `~/opt/gtsam/include/gtsam/config.h:79`. As a result, `PreintegratedCombinedMeasurements` derives from `TangentPreintegration`. That class integrates `theta <- theta + Jr^-1(theta) w dt`, its bias Jacobian is `d theta / d bg`, and its covariance is in the chart `(theta, p, v additive in b_i)`.
   - *Why it matters:* `preintegrator.hpp` promises the "GTSAM scheme (Forster)", the GTSAM block order "[phi, p, v] (decision 5: no permutation needed against GTSAM)", and I-03 "< 1e-9 vs PreintegratedCombinedMeasurements". All three hold only for `ManifoldPreintegration`, which is what the combined class derives from when the flag is OFF. Against the tangent class, `dR` and the gyro-bias Jacobian agree only to O(dt) for general input, and the covariance is in a different chart. The same mismatch affects `backend::Graph::add_imu_factor` when it rebuilds a `CombinedImuFactor` from `PreintegratedDelta`.
   - *Proposed change:* write an ADR that pins `-DGTSAM_TANGENT_PREINTEGRATION=OFF` in `docker/deps.Dockerfile` and `tools/wsl/setup.sh`, and rebuild `~/opt/gtsam`. This needs the controller's and the backend owner's agreement. No public signature changes.
   - *This plan without the change:* the full I-03 check (mean, all bias Jacobians, covariance, prediction) at 1e-9 runs against `gtsam::ManifoldPreintegration`. That class is compiled and exported in both builds; `nm -DC libgtsam.so` lists `ManifoldPreintegration::update`. A second test runs against `PreintegratedCombinedMeasurements` itself. In a manifold build it compares everything. In the current tangent build it compares only what both schemes compute identically, using single-axis gyro input (Task 4).

## Review Focus

1. **Out-of-order or duplicate IMU sample mid-interval** (E-03 reorders 2% of messages): the sample is rejected, the delta is bit-identical to before the call, and the next valid sample integrates with dt measured from the last *accepted* sample. Test: `Preintegrator.RejectedSampleLeavesDeltaUntouchedAndStreamContinues` (Task 2).
2. **Dropped samples cause a dt gap** (E-03 drops 5%): one 15 ms step equals three 5 ms steps when w = 0 and accel is constant, and the covariance stays finite and symmetric. Test: `Preintegrator.GapEqualsSubdividedStepsWithoutRotation` (Task 2). The covariance part is checked in `PreintegratorCov.SymmetricPsdAndZeroWithZeroNoise` (Task 3).
3. **A non-finite first sample after `reset()`**: it is rejected and must not set the start time. The next finite sample becomes the first sample, so `dt_s` stays 0 until the sample after it. Test: `Preintegrator.NonFiniteFirstSampleDoesNotStartInterval` (Task 2).
4. **Keyframe chaining** (pipeline contract: after `reset()` the previous interval's last sample is fed again): prediction through two chained deltas equals prediction through one delta over the whole span, to 1e-9. Test: `Preintegrator.ChainedDeltasEqualSingleDelta` (Task 2).
5. **An upside-down or scale-biased IMU at initialisation** (`a_z < 0`, or `|mean acc|` different from `gravity_mps2`): `R_w_b * mean(acc_b)` still points along +z, and `g_w` uses the config magnitude. Test: `ImuInitializer.UpsideDownAndScaledAccelStillAlignsToPlusZ` (Task 5).

### Task 1: Derivation document

**Files:**
- Create: `docs/derivations/imu_preintegration.md`

**Interfaces:**
- Produces: the formulas Tasks 2 and 3 implement and test. The section numbers are cited in code comments as `docs/derivations/imu_preintegration.md §<n>`.

- [x] **Step 1: Write the document with these sections and exactly these formulas.**

Here `a = s_k.acc_b - ba_lin` and `w = s_k.gyro_b - bg_lin` are the measurements of sample k (k >= 1), `dt = seconds_between(t_{k-1}, t_k)`, `dR_k = so3_exp(w dt)`, `R = dR` before the update, and `x^ = skew(x)`.

  1. *Variables and conventions.* The delta is `(dR = R_bi_bj, dp, dv in b_i)`, linearised at `bias_lin`. Perturbation is right on SO(3). The covariance chart is GTSAM NavState local coordinates: `dR_true = dR Exp(d_phi)`, `dp_true = dp + dR d_p`, `dv_true = dv + dR d_v`. The block order is `[phi, p, v]`. State that this is GTSAM `NavState::retract`, which is why no permutation is needed, and that it is not the additive b_i chart of Forster's paper. Bias Jacobians are right-perturbation for `dR` (`dR(b + db) ~ dR(b) Exp(J_dR_bg dbg)`) and additive for dp and dv. Gravity is not in the deltas.
  2. *Integration rule (mean).* The first sample after `reset()` sets `t_first = t_prev` and integrates nothing. Each later sample applies these updates in order: `dp += dv dt + 0.5 R a dt^2`; `dv += R a dt`; `dR = R dR_k`; `dt_s = seconds_between(t_first, t_k)`.
  3. *Bias Jacobians.* Use the old `R` and the old `J_dR_bg`, and update in this order:
     - `J_dp_ba += J_dv_ba dt - 0.5 R dt^2`
     - `J_dp_bg += J_dv_bg dt - 0.5 R a^ J_dR_bg dt^2`
     - `J_dv_ba += -R dt`
     - `J_dv_bg += -R a^ J_dR_bg dt`
     - `J_dR_bg = dR_k^T J_dR_bg - Jr(w dt) dt`

     Derive each as the exact first derivative of the discrete update. GTSAM `ManifoldPreintegration::update` has the same recursion.
  4. *Covariance recursion.* `Sigma <- A Sigma A^T + B (sa^2/dt) B^T + C (sg^2/dt) C^T`, with `sa = acc_noise_density`, `sg = gyro_noise_density`,
     `A = [[dR_k^T, 0, 0], [-0.5 dR_k^T a^ dt^2, dR_k^T, dR_k^T dt], [-dR_k^T a^ dt, 0, dR_k^T]]`,
     `B = [0; 0.5 dR_k^T dt^2; dR_k^T dt]` and `C = [Jr(w dt) dt; 0; 0]`.
     Include the short derivation: perturb R, p and v in the §1 chart and push them through the §2 update. Note that the result equals GTSAM `NavState::update`'s `F, G1, G2`.
  5. *First-order bias correction and predict.* With `db = x0.bias - bias_lin`:
     - `dR' = dR Exp(J_dR_bg dbg)`
     - `dv' = dv + J_dv_ba dba + J_dv_bg dbg`
     - `dp' = dp + J_dp_ba dba + J_dp_bg dbg`

     Then use the header's predict formulas.
  6. *Checks.* Map each formula to its test: I-01, I-02, I-04 (central differences, step 1e-5), I-05 (Monte Carlo in the §1 chart) and I-03 (GTSAM `ManifoldPreintegration`). Include the note on `GTSAM_TANGENT_PREINTEGRATION` from this plan's Contract issues.

- Set `p->accelerometerCovariance = acc_noise_density^2 * I3` and `p->gyroscopeCovariance = gyro_noise_density^2 * I3` (continuous; GTSAM divides by dt as §4 does).
