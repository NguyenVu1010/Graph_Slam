# gnss Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill in `mss::gnss`: WGS-84 LLA<->ENU geodesy that agrees with `sim/mss_sim/geodesy.py`, the cheap `gate_fix` pre-gate, a chi-square innovation gate with the GNSS position residual and its Jacobian, and the 4-DoF `GnssAligner` (yaw + translation of w to e, lever arm applied).

**Architecture:** `mss_gnss` goes from an INTERFACE target to a STATIC library with four sources (`geodesy.cpp`, `gate.cpp`, `innovation.cpp`, `aligner.cpp`) and one internal header (`core/gnss/src/innovation.hpp`, not installed) holding what the frozen public header has no place for yet (see Contract issues). The aligner is a closed-form 2-D Procrustes fit over running sums, shifted by the first pair for conditioning. Unit tests live in one `test_gnss` binary; G-02..G-04 are synthetic component tests with known answers in `test_gnss_component`.

**Tech Stack:** C++17, GCC 13, Eigen 3.4 (fixed-size only), GTest 1.14, CMake via `tools/wsl/build.sh`. No new dependencies.

**Spec:** `core/gnss/include/mss/gnss/gnss.hpp`, `core/gnss/include/mss/gnss/config.hpp`, `config/default.yaml` (`gnss.*`), `docs/Test_CI_CD.md` section `### gnss` (G-01..G-04), `docs/conventions.md`, `docs/derivations/lie_conventions.md`, `docs/spec.md`, ADR-003/004/005/006/008/009/013 and module ADRs 010, 011 (section 3, GNSS degrader table; GNSS row of the sensor table), 014; reference implementation `sim/mss_sim/geodesy.py` and `tests/python/test_geodesy.py`; `CLAUDE.md`.

## Contract issues

1. **Chi-square gate and GNSS residual have no public declaration.** G-02 is in the gnss section of `Test_CI_CD.md`, but `gnss.hpp` says the chi-square innovation test "lives in the pipeline/backend" and declares nothing for it; the backend's `add_gnss_factor` will need the same residual and Jacobian. Proposed change (needs controller/owner agreement): add to `gnss.hpp`
   `common::Vec3 gnss_residual(const common::Vec3& p_e_g, const common::Pose& T_e_w, const common::Pose& T_w_b, const common::Vec3& p_b_g, Eigen::Matrix<double, 3, 6>* J_r_xi);`
   `common::Status chi_square_gate(const common::Vec3& r_e, const common::Mat3& S_e, double threshold);`
   and `double chi2_gate = 0.0;` to `GnssConfig` (YAML `gnss.chi2_gate: 7.815`, `Range::kPositive`). This plan implements both in `namespace mss::gnss::detail` in `core/gnss/src/innovation.hpp` (compiled into `mss_gnss`, visible to tests through a PRIVATE include dir), so promoting them later is a move, not a rewrite.
2. **`kMinPairsForAlignment` / `kMinHorizontalSpreadM` stay constants.** The header says the gnss module moves them to `GnssConfig` (`gnss.align_min_pairs`, `gnss.align_min_spread_m`), but loading lives in `core/pipeline/src/config.cpp`, the keys in `config/default.yaml`, and `tests/unit/test_interfaces_compile.cpp` static_asserts the constant; all three are outside this module. Proposed change for the pipeline owner: add the two fields (defaults 10 and 1.0) plus `chi2_gate` from issue 1 to `GnssConfig`, `load_config` and `default.yaml`; the gnss module then reads a stored config instead of the constants. This plan uses the constants.

## Review Focus

1. **Non-PD or NaN innovation covariance.** `NaN > threshold` is false, so a naive gate accepts garbage. Expected: `chi_square_gate` returns an error for non-finite `r` or `S` and for `S` that is not positive definite. Pinned: Task 2 `GnssInnovation.NonFiniteOrNonPdIsError`.
2. **Zero or negative variance in `m.cov`.** `gate_fix` only rejects `diag > max_cov_m2` (frozen contract), so `cov = diag(-1, 1, 1)` or all zeros passes it. Expected: the chi-square stage rejects it, never divides by zero. Pinned: Task 2 `GnssGate.NegativeVariancePassesGateButNotChiSquare`.
3. **Large ENU coordinates.** A dataset origin far from the path gives `p_e_g` of order 1e5 m; raw running sums of squares lose about 10 digits. Expected: noise-free alignment exact to 1e-9 rad / 1e-6 m. Pinned: Task 3 `GnssAligner.LargeOffsetStaysExact`.
4. **Yaw near +-180 deg.** Expected: the estimate wraps correctly, not off by 2*pi or flipped. Pinned: Task 3 `GnssAligner.YawNearPiWraps`.
5. **Geodesy near a pole and across the antimeridian.** Expected: round trip < 1 mm, longitude returned in (-180, 180]. Pinned: Task 1 `GnssGeodesy.RoundTripNearPoleAndAntimeridian`.

- [x] **Step 1: Write `docs/derivations/gnss.md`** with these sections, each giving the formula and the code name that implements it:
  1. Geodesy: LLA->ECEF (`N = a / sqrt(1 - e2 sin^2 lat)`, `x = (N+h) cos lat cos lon`, `y = (N+h) cos lat sin lon`, `z = (N(1-e2)+h) sin lat`); ECEF->LLA by Bowring, 5 iterations, exactly as `geodesy.py` (`lon = atan2(y, x)`, `beta = atan2(z a, p b)`, loop `lat = atan2(z + ep2 b sin^3 beta, p - e2 a cos^3 beta)`, `beta = atan2((1-f) sin lat, cos lat)`; then `h = p cos lat + z sin lat - a^2/N`); `R_e_ecef(origin)` rows `[-sin lon, cos lon, 0]`, `[-sin lat cos lon, -sin lat sin lon, cos lat]`, `[cos lat cos lon, cos lat sin lon, sin lat]`; `p_e = R_e_ecef (x_ecef - x0_ecef)`, inverse `x_ecef = x0_ecef + R_e_ecef^T p_e`.
  2. GNSS residual: `r = p_e_g - T_e_w (T_w_b p_b_g)` (3x1, m, in e); variable `T_w_b`, right perturbation `xi = [rho, phi]`; `J_r_xi = [ -R_e_w R_w_b ,  R_e_w R_w_b skew(p_b_g) ]` (3x6). Show the two derivation lines (`p_w_b <- p_w_b + R_w_b rho`; `R_w_b Exp(phi) p_b_g ~ R_w_b p_b_g - R_w_b skew(p_b_g) phi`).
  3. Chi-square gate: `S = Sigma_fix + J_r_xi P J_r_xi^T` (`P` the 6x6 `[rho, phi]` pose covariance; the caller forms `S`), `NIS = r^T S^-1 r` via LLT, reject when `NIS > chi2_3(q)`. Table, 3 DoF: q = 0.95 -> 7.814727903251178; q = 0.99 -> 11.344866730144373. This plan uses q = 0.95 so the expected acceptance of consistent fixes is 95%, the middle of G-02's 90-99% band (planner's call).
  4. Alignment: `a_i = p_w_g,i - p_w_g,0`, `b_i = p_e_g,i - p_e_g,0` (shift by the first pair, conditioning); running sums `n`, `sum a`, `sum b`, `C = sum a_h b_h^T` (2x2, horizontal parts), `sum |a_h|^2`; centred `C_c = C - (sum a_h)(sum b_h)^T / n`; `yaw = atan2(C_c(0,1) - C_c(1,0), C_c(0,0) + C_c(1,1))` (maximises `sum b_c^T Rz(yaw) a_c`); `p_e_w = mean_e - Rz(yaw) mean_w` with un-shifted means; spread `sqrt(max(0, sum|a_h|^2/n - |sum a_h / n|^2))`; observability note `sigma_yaw ~ sigma_h / sqrt(sum |a_c,h|^2)`: at sigma_h = 1.0 m, 5 Hz, 1 m/s, 30 m straight this is about 0.54 deg (why G-03 uses a smaller sigma, Task 3).
